# Saint Bait

Помощник для Russian Fishing 4, Windows, Python 3.14. Интерфейс показывает снасти,
состояние компонентов, фактическую прочность и заполнение садка. Полный состав
показывается для используемых снастей в руках или на подставках; снасти из рюкзака
не добавляются. Тип снасти определяется автоматически, ручного переключателя режимов нет.
Открытие программы
запускает наблюдение; управление игрой начинается только по кнопке «Старт».

Сессия заканчивается при заполнении фактической ёмкости садка или по таймеру
(максимум два часа). F8 останавливает управление. Подробности ловли — в README.txt.

## Уловы и цены

Вкладка «Уловы» содержит уловы точки и собственный садок. Журнал автоматически
записывает подтверждённый результат, водоём, координаты, дату, рыбу, вес, наживку,
клипсу заброса и снимок компонентов снасти. Нажатие на запись открывает подробности.
Для рыб, пойманных до запуска журнала, состав снасти и клипса могут быть неизвестны.
Данные о применённой прикормке пока отмечаются как неизвестные: выбор прикормки
сам по себе не доказывает её применение.

При открытом рынке программа читает цены и сохраняет наблюдения. Она не меняет
окно продажи и не продаёт рыбу автоматически. Приблизительные цены выводятся
только в окне бота: для рыбы, уловов точки и оценённой части садка.
Оценка учитывает водоём рынка, вид, категорию, вес и свежесть; обычно нужны
минимум три разные сопоставимые рыбы за последние сутки. В деталях видны число
примеров и время наблюдений. Неизвестная цена не считается нулевой.

Локальные данные находятся рядом с EXE в `catches.sqlite3`. Сетевые сбои
не мешают локальному журналу. Адрес общей базы, публичный ключ и репозиторий
обновлений заданы в `saint_bait/deployment.py`; пользователям вводить их не нужно.
Для отдельного собственного развёртывания:

1. В SQL Editor проекта выполнить `backend/supabase.sql`.
2. Разрешить Anonymous sign-ins в настройках Authentication.
3. В `saint_bait/deployment.py` указать HTTPS-адрес проекта и публичный publishable/anon ключ, затем пересобрать EXE.

Секретный `service_role`/`sb_secret_` ключ в бот добавлять нельзя.
Общая лента обновляется каждые пять секунд: тот же водоём и ±3 по каждой
координате. Передаются только игровые записи уловов и рыночные наблюдения;
игровые логины и пароли не нужны.

## Запуск из исходников

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe podust.py
```

Игра должна быть запущена. Модуль данных использует внешний доступ только для
чтения; внедрение DLL и запись в память игры не используются. Обновление клиента
игры может потребовать адаптации наблюдателя. Защита снасти снижает риск
перегрузки, но задержки системы и резкие скачки нагрузки остаются возможны.

## Сборка и обновления

`Build Saint Bait.ps1` запускает проверки, собирает EXE в `release-build` и
копирует свежий `Saint Bait.exe` на рабочий стол. Перед заменой закройте экземпляр
с рабочего стола; другой экземпляр из каталога разработки не мешает сборке.

```powershell
& '.\Build Saint Bait.ps1'
& '.\Prepare Release.ps1' -Version 1.1.1 -Executable '.\release-build\Podust.exe'
```

Бот проверяет GitHub Releases `l2gorynych/saint-bait`. Новая версия загружается
в фоне, проверяется по размеру и SHA-256 из `update.json` и устанавливается
при закрытии приложения. Настройки и локальная база сохраняются.
Токен публикации в EXE не включается. Настройки, логи, базы, сессии
и старый частный прототип исключены из исходников репозитория.
